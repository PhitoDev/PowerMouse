macOS publishing secrets for PowerMouse

The Publish macOS workflow signs, notarizes, packages, and uploads a macOS build. These GitHub repository secrets give the runner temporary access to the Apple Developer assets it needs.

Recommended setup flow

Use a dedicated Apple Developer certificate exported as a password-protected .p12, then store the values as GitHub Actions secrets.

Create or identify the Apple Developer account

Sign in to Apple Developer with the account that owns the PowerMouse team membership. This Apple ID becomes APPLE_ID, and the team's 10-character identifier becomes APPLE_TEAM_ID.

Create a Developer ID Application certificate

In Apple Developer, open Certificates, Identifiers & Profiles, create a new certificate, and choose Developer ID Application. Upload a certificate signing request from Keychain Access when prompted. 

Keychain Access → Certificate Assistant → Request a Certificate From a Certificate Authority…

Use Developer ID Application for distributable macOS apps outside the Mac App Store. The workflow signs the app bundle with this identity.

Export the certificate and private key

Install the downloaded certificate, then export the certificate plus private key from Keychain Access as a .p12 file. Choose a strong export password; that password becomes MACOS_CERTIFICATE_PASSWORD.

Encode the .p12 for GitHub

GitHub secrets store text, so convert the binary certificate file to one base64 string.

base64 -i DeveloperIDApplication.p12 | tr -d '\n' | pbcopy

The clipboard value becomes MACOS_CERTIFICATE.

Create an app-specific password for notarization

Go to account.apple.com, open Sign-In and Security, then create an App-Specific Password. Store the generated password as APPLE_APP_PASSWORD.

Add secrets to the repository

In GitHub, open Settings → Secrets and variables → Actions → New repository secret and add every value below. Keep secret names exact; GitHub Actions secret names are case-sensitive in workflow references.

Each secret, explained

These values map directly to the environment variables consumed by .github/workflows/publish-macos.yml.

MACOS_CERTIFICATE

Base64-encoded signing certificate

The encoded contents of the password-protected .p12 file that contains the Developer ID Application certificate and its private key.

Used byCertificate import step
SourceExported Keychain .p12
  1. Open Keychain Access and locate your Developer ID Application certificate.
  2. Expand the certificate and confirm the private key is present underneath it.
  3. Select both, then choose File → Export Items….
  4. Save as DeveloperIDApplication.p12 and set a strong export password.
  5. Run the command below and paste the clipboard into the GitHub secret.
base64 -i DeveloperIDApplication.p12 | tr -d '\n' | pbcopy

Do not commit the .p12 file or its base64 output. Delete local temporary copies after the secret is saved.

MACOS_CERTIFICATE_PASSWORD

Password for the exported certificate

The password you typed when exporting the .p12 certificate from Keychain Access.

Used bysecurity import
FormatPlain text secret
  1. Generate a strong password with a password manager or command line.
  2. Use it as the export password when Keychain Access asks for one.
  3. Store the same value as MACOS_CERTIFICATE_PASSWORD.
openssl rand -base64 32

This is not your Apple ID password. It only protects the exported .p12 file.

MACOS_SIGNING_IDENTITY

Developer ID Application identity

The code-signing identity Briefcase passes to Apple’s codesign tooling when packaging the app.

Used bybriefcase package --identity
ExampleDeveloper ID Application: Name (TEAMID)

After installing the certificate locally, list matching identities:

security find-identity -v -p codesigning

Use either the full readable identity name or the 40-character hash shown by the command.

The readable name is easier to audit; the hash is more precise if multiple certificates share a similar name.

APPLE_ID

Apple ID used for notarization

The email address for the Apple account that belongs to the Apple Developer team.

Used byxcrun notarytool
FormatEmail address
  1. Sign in at developer.apple.com/account.
  2. Confirm the account can access the team that owns the signing certificate.
  3. Store the Apple ID email as APPLE_ID.

Use an Apple Developer account with the least privileges that can sign and notarize releases.

APPLE_TEAM_ID

10-character Apple Developer Team ID

The identifier Apple uses to associate notarization credentials with the correct developer team.

Used byNotary profile name
FormatAB12C3D4EF
  1. Open Apple Developer Account.
  2. Go to Membership details.
  3. Copy the Team ID value.

You can also infer it from a Developer ID identity name:

Developer ID Application: Example Company (AB12C3D4EF)
APPLE_APP_PASSWORD

App-specific password for notarytool

A one-purpose Apple password used by xcrun notarytool to submit the signed app for notarization.

Used bynotarytool store-credentials
Created atApple Account
  1. Open account.apple.com.
  2. Go to Sign-In and Security → App-Specific Passwords.
  3. Create a password named something like PowerMouse GitHub Releases.
  4. Copy the generated value immediately and save it as APPLE_APP_PASSWORD.

If this value is lost, revoke it and create a new one. Apple only shows it once.

GitHub secret names

Copy these names exactly when creating repository secrets.

Secret Value to paste How to rotate
MACOS_CERTIFICATE Base64 output from the exported .p12 file. Export a new certificate/private key pair and replace the secret.
MACOS_CERTIFICATE_PASSWORD Password used when exporting the .p12. Re-export the .p12 with a new password and update both certificate secrets.
MACOS_SIGNING_IDENTITY Developer ID Application name or 40-character identity hash. Replace when the signing certificate changes.
APPLE_ID Apple Developer account email. Replace if notarization ownership moves to another account.
APPLE_TEAM_ID 10-character Apple Developer Team ID. Replace only when changing developer teams.
APPLE_APP_PASSWORD Apple app-specific password. Revoke the old app-specific password and create a new one.

Sanity check before releasing

Trigger the workflow after saving all secrets. If signing fails, first check MACOS_SIGNING_IDENTITY against the certificate imported into the runner. If notarization fails, verify APPLE_ID, APPLE_TEAM_ID, and APPLE_APP_PASSWORD by running xcrun notarytool store-credentials locally with the same values.
