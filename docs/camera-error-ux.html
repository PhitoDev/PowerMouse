UX principles applied

Design rationale

1Never crash, always recover

A missing camera is an expected runtime condition (unplugged, used by another app, virtual cam disabled). Treat it as a state, not a fatal error.

2Speak the user's language

"We couldn't reach your camera" beats "RuntimeError: Failed to open camera at index 1400". The raw trace is still available for power users behind a disclosure.

3Offer the next step, not just the problem

The panel shows a primary action (Use this camera) and a secondary recovery (Refresh devices). No dead ends.

4Preserve context

Recovery happens inside the app shell — sidebar, profiles, and settings remain visible — so users feel oriented, not displaced.

5Make the broken thing visible

The previously-used camera is listed with a Missing badge, confirming the diagnosis instead of hiding it.

6Persist the fix

Selecting a new camera updates the active profile, so the user isn't asked again on next launch.

Implementation sketch

For engineers
  1. In main(), wrap camera_controller.start_stream() in a try/except (RuntimeError, ValueError). On failure, mount the camera widget in a "needs recovery" state instead of raising.
  2. Add device_manager.get_devices() output to the recovery panel and mark the profile's saved camera as missing if it isn't in the list.
  3. Wire the primary button to call profile_manager.update_profile() with the chosen camera and then camera_controller + inference_controller restart.
  4. Refresh devices simply re-runs device_manager.get_devices() — no app restart required.
  5. Keep the original traceback log file untouched for diagnostics; surface it via Show technical details so power users can still copy it.
